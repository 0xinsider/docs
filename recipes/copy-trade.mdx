Build a follow list of S and A wallets and get a signal when one of them trades. 0xinsider reads market data. It places no orders.

Every request needs a Pro API key. See [Authentication](/authentication).

## 1. Build the follow list

[`GET /api/v1/leaderboard`](/api-reference/endpoint/get-leaderboard) lists graded wallets.

- The leaderboard holds S, A, and B wallets only.
- There is no `min_grade` filter. Filter on `grade` in code.
- `realized_pnl` is the banked figure. `pnl` includes open positions.
- `strategy_type` is on each entry. Pass `strategy` to keep one style. See [Strategy types](/concepts/strategy-types).
- A `400` with `error.reason="cursor_expired"` means the ranking changed. Request page one again.

```python
import os

import requests

BASE = "https://api.0xinsider.com/api/v1"
H = {"Authorization": f"Bearer {os.environ['OXINSIDER_API_KEY']}"}

leaders = requests.get(
    f"{BASE}/leaderboard", params={"limit": 100}, headers=H, timeout=30
).json()
follow = [t["address"] for t in leaders["data"] if t["grade"] in ("S", "A")]
```

```bash
curl -H "Authorization: Bearer $OXINSIDER_API_KEY" \
  "https://api.0xinsider.com/api/v1/leaderboard?strategy=swing_trader&limit=50"
```

## 2. Score each wallet

[`POST /api/v1/traders/batch`](/api-reference/endpoint/batch-get-traders) reads up to 25 wallets in one call. Add `expand: ["quant_metrics"]` to get `copy_score`.

- `traders` takes 1 to 25 items. Split a longer list.
- `quant_metrics` appears only when a computed row under six hours old exists. Handle a missing key.
- `copy_score` is 0 to 100. It subtracts penalties for a small sample, concentration, oversized bets, large single losses, and inconsistent edge.
- `smart_score` is the same base score without those penalties.
- Each item has its own `status`. One bad wallet does not fail the batch.

```python
batch = requests.post(
    f"{BASE}/traders/batch",
    json={"traders": follow[:25], "expand": ["quant_metrics"]},
    headers=H,
    timeout=30,
).json()

ranked = []
for item in batch["data"]:
    if item["status"] != "ok":
        print("skip:", item["input"], item["error"]["message"])
        continue
    t = item["data"]
    qm = t.get("quant_metrics") or {}
    ranked.append((qm.get("copy_score"), t["address"], t["username"], t["grade"]))

ranked.sort(key=lambda r: r[0] or 0, reverse=True)
for score, address, username, grade in ranked:
    print(score, grade, username or address[:10])
```

## 3. Watch for new trades

[`GET /api/v1/whale-trades`](/api-reference/endpoint/get-whale-trades) has no wallet filter. Match `trader.address` in code.

- `min_grade=A` returns S and A wallets.
- The list is newest first. Deduplicate on `id`.
- `side` is `BUY` or `SELL`. `outcome` is the traded outcome label and is null on a multi-outcome market.
- `token_id` names the traded outcome on the Polymarket CLOB. Your own order client needs it.

```python
follow_set = {a.lower() for a in follow}
seen = set()


def new_moves(min_size=10000):
    page = requests.get(
        f"{BASE}/whale-trades",
        params={"min_grade": "A", "min_size": min_size, "limit": 100},
        headers=H,
        timeout=30,
    ).json()
    moves = []
    for tr in page["data"]:
        if tr["id"] in seen:
            continue
        seen.add(tr["id"])
        if tr["trader"]["address"].lower() in follow_set:
            moves.append(tr)
    return moves


for tr in new_moves():
    who = tr["trader"]["username"] or tr["trader"]["address"][:10]
    print(
        who, tr["side"], tr["outcome"], f'${tr["size_usd"]:,.0f}',
        "@", tr["price"], tr["market"]["title"], tr["token_id"],
    )
```

For push delivery, subscribe to `whale_trades_inserted` and run the same match. See [Alert bot](/recipes/alert-bot).

## 4. Read the entry and exit history

[`GET /api/v1/trader/{address}/position-timeline`](/api-reference/endpoint/get-trader-position-timeline) returns every stored fill for one wallet in one market.

- `condition_id` is required. Take it from `market.condition_id` on the trade.
- Events are newest first. `running_amount` and `running_avg_price` are computed on the server.
- `running_avg_price` does not change on a sell.
- A `404` with `error.reason="trader_not_tracked"` is terminal. Stop the requests for that wallet.

```bash
curl -H "Authorization: Bearer $OXINSIDER_API_KEY" \
  "https://api.0xinsider.com/api/v1/trader/0x204f72f35326db932158cba6adff0b9a1da95e14/position-timeline?condition_id=0x123..."
```

## Scope

- There is no per-wallet positions endpoint and no per-wallet push channel. Match addresses in code.
- The timeline exists only for wallets in the active sync tiers.
- No endpoint places, cancels, or reads an order. Route an order through your own Polymarket client.
