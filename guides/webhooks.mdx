Webhooks send a signed HTTPS POST to your endpoint when a subscribed event fires. Use them in place of a polling loop.

## Choose event types

[List Webhook Events](/api-reference/endpoint/list-webhook-events) returns the catalog. Each entry has `id`, `description`, `payload_shape`, and `status`.

| Event type | Status | Pro only | `data` fields |
|---|---|---|---|
| `whale_trades_inserted` | `active` | Yes | `count` |
| `wallet_grade_changed` | `active` | Yes | `wallet`, `trader_id`, `old_grade`, `new_grade`, `direction`, `skill_index`, `final_score`, `date` |
| `insider_radar_flag_raised` | `active` | Yes | `trade_id`, `wallet`, `trader_id`, `condition_id`, `suspicion_score`, `track`, `side`, `size`, `price` |
| `smart_money_flow_detected` | `active` | Yes | `condition_id`, `net_flow_usd`, `abs_net_flow_usd`, `dominant_side`, `grade_floor`, `whale_trade_count`, `window` |
| `whale_trader_synced` | `active` | No | `trader_id`, `wallet` |
| `large_positions_updated` | `active` | No | `count` |
| `live_sports_updated` | `dormant` | No | none |

- A `dormant` type accepts a subscription but sends no delivery yet.
- A Pro-only type delivers only to a key on an active Pro subscription.
- `whale_trades_inserted` says that new trades landed. Read them from [Get Whale Trades](/api-reference/endpoint/get-whale-trades).

## Create the endpoint

```bash
curl -X POST \
  -H "Authorization: Bearer $OXINSIDER_API_KEY" \
  -H "Idempotency-Key: webhook-create-2026-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Production webhook",
    "url": "https://api.yourapp.com/webhooks/0xinsider",
    "event_types": ["whale_trades_inserted"]
  }' \
  "https://api.0xinsider.com/api/v1/webhooks"
```

- `url` must be a public HTTPS URL with no credentials. The API rejects `localhost`, `.local`, `.internal`, and private or loopback IP addresses.
- One account holds at most 10 endpoints. A second endpoint with the same URL returns `400`.
- The response shows `signing_secret` and `verification.token` once. Store both now.
- `signing_secret` starts with `whsec_`. The token starts with `whv_` and expires 24 hours after creation.
- The new endpoint has `status: "pending_verification"`. It receives nothing until you verify it.

## Verify the endpoint

Send the token to [Verify Webhook](/api-reference/endpoint/verify-webhook) before the token expires.

```bash
curl -X POST \
  -H "Authorization: Bearer $OXINSIDER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"verification_token": "whv_3c2e...redacted"}' \
  "https://api.0xinsider.com/api/v1/webhooks/42/verify"
```

- Success sets `status` to `active` and `verified_at` to the current time.
- The call sends no test delivery to your endpoint.
- An invalid or expired token returns `400` with `error.param="verification_token"`. Delete the endpoint and create it again to get a new token.

## Receive a delivery

Every delivery is a `POST` with a JSON body and a `User-Agent` of `0xinsider-webhooks/1.0`.

| Header | Value |
|---|---|
| `x-0xinsider-signature` | `v1=<hex>`, the HMAC-SHA256 signature. |
| `x-0xinsider-timestamp` | Unix seconds at signing time. |
| `x-0xinsider-event-id` | Stable event id. It is the same on every retry of one event. |
| `x-0xinsider-event-type` | The event type. |
| `x-0xinsider-delivery-id` | The `id` of the row in the delivery log. |
| `x-0xinsider-delivery-attempt` | Attempt counter. It starts at 1. |
| `idempotency-key` | Stable key for this endpoint and event pair. |

The body has four fields:

```json
{
  "id": "evt_whale_trades_inserted_rtds_9f2c...redacted",
  "type": "whale_trades_inserted",
  "created_at": "2026-06-17T14:28:20Z",
  "data": { "count": 7 }
}
```

Return any `2xx` status within 15 seconds. Acknowledge first, then process the event.

## Check the signature

The signature covers the timestamp and the raw body, joined by a dot:

```
signature = "v1=" + hex( HMAC_SHA256( signing_secret, timestamp + "." + raw_body ) )
```

- Use the raw request bytes. A parsed and re-serialized body changes the HMAC.
- Use the full `whsec_...` string as the key.
- Reject a timestamp more than 300 seconds from your clock.
- Compare with a constant-time function.
- Deduplicate on `x-0xinsider-event-id` before you act on the event.

<CodeGroup>
```javascript Node (Express)
import express from "express";
import crypto from "node:crypto";

const SECRET = process.env.OXINSIDER_WEBHOOK_SECRET;
const TOLERANCE_SECONDS = 300;

function verify(rawBody, signatureHeader, timestampHeader) {
  const ts = Number(timestampHeader);
  if (!Number.isFinite(ts)) return false;
  if (Math.abs(Date.now() / 1000 - ts) > TOLERANCE_SECONDS) return false;

  const expected =
    "v1=" +
    crypto
      .createHmac("sha256", SECRET)
      .update(`${timestampHeader}.${rawBody}`)
      .digest("hex");

  // The header may carry a comma-separated list; accept any match.
  return signatureHeader
    .split(",")
    .map((s) => s.trim())
    .some((candidate) => {
      const a = Buffer.from(candidate);
      const b = Buffer.from(expected);
      return a.length === b.length && crypto.timingSafeEqual(a, b);
    });
}

const app = express();

// Capture the raw body; do NOT use a JSON parser before verifying.
app.post(
  "/webhooks/0xinsider",
  express.raw({ type: "application/json" }),
  (req, res) => {
    const rawBody = req.body.toString("utf8");
    const ok = verify(
      rawBody,
      req.get("x-0xinsider-signature") ?? "",
      req.get("x-0xinsider-timestamp") ?? ""
    );
    if (!ok) return res.status(400).send("bad signature");

    const event = JSON.parse(rawBody);
    // Dedupe on event.id, then ACK fast and process async.
    res.status(200).send("ok");
    handleEvent(event).catch(console.error);
  }
);
```

```python Python (Flask)
import hashlib
import hmac
import os
import time
from flask import Flask, request

SECRET = os.environ["OXINSIDER_WEBHOOK_SECRET"].encode()
TOLERANCE_SECONDS = 300

def verify(raw_body: bytes, signature_header: str, timestamp_header: str) -> bool:
    try:
        ts = int(timestamp_header)
    except (TypeError, ValueError):
        return False
    if abs(time.time() - ts) > TOLERANCE_SECONDS:
        return False

    signed = f"{timestamp_header}.".encode() + raw_body
    expected = "v1=" + hmac.new(SECRET, signed, hashlib.sha256).hexdigest()

    # The header may carry a comma-separated list; accept any match.
    return any(
        hmac.compare_digest(part.strip(), expected)
        for part in signature_header.split(",")
    )

app = Flask(__name__)

@app.post("/webhooks/0xinsider")
def receive():
    raw_body = request.get_data()  # raw bytes, before any JSON parse
    ok = verify(
        raw_body,
        request.headers.get("x-0xinsider-signature", ""),
        request.headers.get("x-0xinsider-timestamp", ""),
    )
    if not ok:
        return "bad signature", 400

    event = request.get_json()
    # Dedupe on event["id"], then return 200 quickly.
    return "ok", 200
```
</CodeGroup>

## Handle retries

A non-`2xx` status, a connection error, or a timeout fails the attempt. A delivery gets at most 8 attempts.

| Failed attempt | Next attempt after |
|---|---|
| 1 | 1 minute |
| 2 | 2 minutes |
| 3 | 4 minutes |
| 4 | 8 minutes |
| 5 | 16 minutes |
| 6 | 32 minutes |
| 7 | 60 minutes |
| 8 | none, the delivery moves to `dead_letter` |

- The worker polls every 10 seconds, so each delay can run up to 10 seconds longer.
- `failure_count` on the endpoint counts consecutive failed attempts. One success resets it to 0.
- After 8 consecutive failed attempts, the endpoint `status` becomes `disabled`. Set `enabled: true` with [Update Webhook](/api-reference/endpoint/update-webhook) to resume.

<Warning>
While an endpoint is `disabled`, the API queues nothing for it and moves every queued delivery to `dead_letter`.
</Warning>

Read the outcome of each attempt in [List Webhook Deliveries](/api-reference/endpoint/list-webhook-deliveries).

## Replay after downtime

Only `whale_trades_inserted` has a durable replay. Use [Get Event Replay Since](/api-reference/endpoint/get-event-replay-since) to fill the gap.

1. Store `next_cursor` from every replay response in durable storage.
2. After the outage, request `/api/v1/events/feed/since?cursor=<saved cursor>`.
3. Process each event, then store the new `next_cursor`.
4. Repeat while `has_more` is `true`.

For the other event types, read `status` and `last_error` in the delivery log. A `dead_letter` row is not sent again.

## Rotate the secret

Rotate after the secret enters git, a log, a screenshot, or another unsafe place.

```bash
curl -X POST \
  -H "Authorization: Bearer $OXINSIDER_API_KEY" \
  -H "Idempotency-Key: webhook-rotate-2026-06-01" \
  "https://api.0xinsider.com/api/v1/webhooks/42/rotate-secret"
```

1. Call [Rotate Webhook Secret](/api-reference/endpoint/rotate-webhook-secret). The old secret stops at once. There is no overlap window.
2. Store the new `signing_secret` from the response. It appears only once.
3. Deploy the new secret to every receiver within 1 minute. A delivery that fails your check retries after that delay with the same secret.
4. Read the delivery log and check that new rows show `status: "delivered"`.

The call returns `409` with `error.reason="webhook_delivery_in_progress"` while one delivery is in flight. Retry after that request completes.

## No public endpoint

Use a polling loop instead. [Get Whale Trades](/api-reference/endpoint/get-whale-trades) is the live feed, [Get Event Replay Since](/api-reference/endpoint/get-event-replay-since) replays events, and [Get Stream](/api-reference/endpoint/get-stream) opens an SSE stream.
