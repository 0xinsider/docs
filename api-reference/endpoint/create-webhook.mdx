Register an HTTPS endpoint for [webhook events](/guides/webhooks#choose-event-types). The endpoint starts as `pending_verification` and receives nothing until you verify it.

## Create the endpoint

- `url` must be a public HTTPS URL with no credentials. The API rejects `localhost`, `.local`, `.internal`, and private or loopback IP addresses.
- `event_types` needs one or more types from [List Webhook Events](/api-reference/endpoint/list-webhook-events). Four types deliver only to a key on an active Pro subscription.
- One account holds at most 10 endpoints. A second endpoint with the same URL returns `400`.
- The response shows `signing_secret` and `verification.token` once. Store both now.
- `verification.expires_at` is 24 hours after creation.

```bash
curl -X POST \
  -H "Authorization: Bearer $OXINSIDER_API_KEY" \
  -H "Idempotency-Key: webhook-create-2026-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Production webhook",
    "url": "https://api.yourapp.com/webhooks/0xinsider",
    "event_types": ["whale_trades_inserted"]
  }' \
  "https://api.0xinsider.com/api/v1/webhooks"
```

## Handle the Idempotency-Key 409

Send `Idempotency-Key` when a timeout hides the result. The same key and body return the original response.

1. On `409` with `error.reason="idempotency_in_progress"`, keep the same key and body.
2. Wait a few seconds, then send the same request again.
3. On `422`, the key was used with a different body. Send a new key.
