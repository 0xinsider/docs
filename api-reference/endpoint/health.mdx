---
title: "Health Check"
openapi: "GET /api/v1/health"
---

Check API liveness, database and cache connectivity, and background job health. No key is needed. Use it for a status page or a startup check.

## Read the status

- `status` is `ok`, `degraded`, `down`, or `maintenance`. `db` and `cache` are booleans.
- `status` is `down` when the database probe fails or background jobs are down. `maintenance` marks a planned window; then `db` and `cache` read `true` without a probe.
- `subsystems.background_jobs.status` is `ok`, `degraded`, `down`, or `not_checked`. The counts (`total`, `healthy`, `stale`, `missing`, `invalid`, `unconfigured`, `paused`) are aggregates only.
- `paused` counts heavy jobs idle while the heavy executor is off. A paused job yields `degraded`, never `down`.
- The response exposes no job names, Redis keys, raw errors, wallet addresses, or condition IDs.
- The limit is 120 requests per minute per IP. Past that, the endpoint returns `429` with `Retry-After`.

```bash
curl "https://api.0xinsider.com/api/v1/health"
```

## Cache the status

The response carries an `ETag`. Send it as `If-None-Match` to get `304 Not Modified` with an empty body when the status is unchanged.
