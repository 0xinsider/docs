---
title: "Get Event Replay Since"
openapi: "GET /api/v1/events/feed/since"
---

Replay durable `whale_trades_inserted` events after a saved cursor. Use this endpoint after a worker restart, a stream disconnect, or a webhook outage.

## Read the window

- `data[].type` is always `whale_trades_inserted`. Other event types have no durable replay.
- `data[].payload` holds `count`, `whale_alert_id`, `condition_id`, `trader_id`, and `platform`.
- Events are ordered by `sequence`, the `whale_alerts.id` value, from low to high.
- Without `cursor`, the response holds the newest `limit` events and `has_more` is `false`.
- With `cursor`, the response holds events strictly after it. `limit` accepts 1 to 100 and defaults to 50.
- `next_cursor` is always present. On an empty page it equals the request cursor.
- `meta.completeness.status` is `complete` or `caught_up`. `meta.retention.cursor_expired` is always `false`.

```bash
curl -H "Authorization: Bearer $OXINSIDER_API_KEY" \
  "https://api.0xinsider.com/api/v1/events/feed/since?cursor=$REPLAY_CURSOR&limit=100"
```

## Walk the cursor

1. Store `next_cursor` in durable storage after each page.
2. Pass it as `cursor` on the next request.
3. Repeat while `has_more` is `true`.
4. Process each event once. A restart can replay a page you already saw.

## Handle the 400

A malformed cursor returns `400` with `error.param="cursor"`. Use only a `next_cursor` value from a prior response. Do not build a cursor by hand.
