Every error except `408` returns a JSON envelope. Branch on `error.code`, then on `error.reason`, and honor `Retry-After` on the four retryable errors.

## Read the envelope

```json
{
  "object": "error",
  "error": {
    "code": "not_found",
    "message": "No pick of the day is published yet. Recommended next retry at 2026-08-29T14:00:00+00:00. Schedule against error.retry_at or the Retry-After header instead of polling.",
    "doc_url": "https://docs.0xinsider.com/api-reference/endpoint/get-pick-of-the-day",
    "param": null,
    "reason": "pick_not_released",
    "retry_at": "2026-08-29T14:00:00+00:00"
  },
  "meta": { "request_id": "req_example", "cached": false, "cost": 1 }
}
```

| Field | Meaning |
|---|---|
| `error.code` | One of nine stable values. Branch on it in code. |
| `error.message` | Text for a log line. Do not parse it. |
| `error.doc_url` | Link to the page that explains the error. Can be `null`. |
| `error.param` | The request parameter at fault on a `400`. Can be `null`. |
| `error.reason` | A more specific cause, present only when one exists. |
| `error.retry_at` | RFC3339 instant of the next useful request. Present only on retryable errors. |
| `meta.request_id` | Include it in a support request. |

<Warning>
  `408 Request Timeout` has an empty body. The 30-second transport timeout fires before the server builds the JSON envelope. Check the status before you parse.
</Warning>

## Branch on the code

| HTTP | `error.code` | Cause | Action |
|---|---|---|---|
| `400` | `bad_request` | A parameter is invalid. | Read `error.param`, then `error.message`. Fix the input. |
| `401` | `invalid_api_key` | The key is missing, malformed, or revoked. | Check the `Authorization` header. See [Authentication](/authentication). |
| `402` | `subscription_required` | The key is valid, but the account has no active Pro subscription. | Subscribe at [Pricing](https://0xinsider.com/pricing). |
| `403` | `forbidden` | The account was deleted, or the request IP is blocked. | Contact support. |
| `404` | `not_found` | The resource does not exist, or `error.reason` names a specific cause. | Branch on `error.reason`. |
| `408` | none | The request exceeded the 30-second transport timeout. | Retry once. Do not parse the body. |
| `409` | `bad_request` | A webhook mutation with the same `Idempotency-Key` is still in progress. | Retry with the same key and body. |
| `423` | `account_locked` | The account is locked. | Contact support. |
| `429` | `rate_limited` | The request budget or the batch item budget is spent. | Wait `Retry-After` seconds. See [Rate Limits](/rate-limits). |
| `500` | `internal_error` | A server bug. | Retry once. Send `meta.request_id` to support. |
| `503` | `rate_limit_unavailable` | The rate limiter is unavailable, or `error.reason` is `read_model_warming`. | Branch on `error.reason`. |

## Branch on the reason

`error.reason` is additive. `error.code` keeps its published value, so an old client still works.

| `error.reason` | HTTP | Meaning | Action |
|---|---|---|---|
| `pick_not_released` | `404` | No pick is published for the current product day. | Schedule one request for `retry_at`. Do not poll. |
| `unknown_endpoint` | `404` | The path is not a route on this API. | Read `GET /api/v1`. Do not retry. |
| `trader_not_tracked` | `404` | The wallet is real, but the trader sits outside the sync tiers. | Stop requesting this wallet. |
| `cursor_expired` | `400` | The cursor went stale after an upstream refresh. `error.param` is `cursor`. | Request the first page again and walk forward. |
| `read_model_warming` | `503` | This endpoint cannot serve its read model yet. | Retry only this route after `Retry-After`. Do not back off other routes. |
| `idempotency_in_progress` | `409` | A request with the same `Idempotency-Key` is still in progress. | Retry with the same key and body. |
| `webhook_delivery_in_progress` | `409` | The destination has an active delivery. `error.param` is `endpoint`. | Retry the change after the delivery ends. |

A `503` with no `reason` means the rate limiter failed closed. Back off every authenticated route for `Retry-After` seconds.

## Honor Retry-After

Four errors carry `Retry-After` in seconds and `error.retry_at` as an RFC3339 instant:

- `429 rate_limited`
- `503 rate_limit_unavailable` with no reason
- `503` with `error.reason="read_model_warming"`
- `404` with `error.reason="pick_not_released"`

Both name the same instant. Use the header for the sleep duration, because it is immune to clock skew. Use `retry_at` to schedule an absolute wake.

## Handle errors in code

<CodeGroup>
```javascript JavaScript
async function call(path, opts = {}) {
  const res = await fetch(`https://api.0xinsider.com/api/v1${path}`, {
    headers: { Authorization: `Bearer ${process.env.OXINSIDER_API_KEY}` },
    ...opts,
  });
  if (res.status === 408) {
    throw new Error("0xinsider request exceeded the 30-second transport timeout");
  }
  const body = await res.json();
  if (res.ok) return body;

  const { code, message, param, reason } = body.error;
  const retryAfter = res.headers.get("retry-after");
  if (retryAfter && reason !== "pick_not_released") {
    await new Promise(r => setTimeout(r, Number(retryAfter) * 1000));
    return call(path, opts);
  }
  if (reason === "cursor_expired") {
    throw new Error("cursor expired: restart from the first page");
  }
  if (code === "subscription_required") {
    throw new Error("Pro subscription required");
  }
  throw new Error(`${code}: ${message}${param ? ` (param=${param})` : ""}`);
}
```

```python Python
import os, time, requests

BASE = "https://api.0xinsider.com/api/v1"
H = {"Authorization": f"Bearer {os.environ['OXINSIDER_API_KEY']}"}

def call(path, **params):
    r = requests.get(f"{BASE}{path}", headers=H, params=params)
    if r.status_code == 408:
        raise TimeoutError("0xinsider request exceeded the 30-second transport timeout")
    body = r.json()
    if r.ok:
        return body

    err = body["error"]
    retry_after = r.headers.get("Retry-After")
    if retry_after and err.get("reason") != "pick_not_released":
        time.sleep(int(retry_after))
        return call(path, **params)
    if err.get("reason") == "cursor_expired":
        raise RuntimeError("cursor expired: restart from the first page")
    if err["code"] == "subscription_required":
        raise RuntimeError("Pro subscription required")
    raise RuntimeError(f"{err['code']}: {err['message']}")
```
</CodeGroup>

Schedule a `pick_not_released` wake with a timer or a queue. Do not sleep a worker thread on it.

## Read batch item errors

A batch endpoint can return `200` with failed items. Read `data[i].status` for every item. When `status` is `error`, `data[i].error` carries `code` and `message` in the same shape as `error` above.

## Fix common errors

<AccordionGroup>
  <Accordion title="401 invalid_api_key">
    - Send `Authorization: Bearer oxi_sk_live_...`.
    - A full key has 76 characters. Copy the full string.
    - A regenerated key revokes the old one. Update every consumer.
  </Accordion>
  <Accordion title="402 subscription_required">
    The key is fine. The subscription is not. Re-subscribe at [Pricing](https://0xinsider.com/pricing). The same key resumes.
  </Accordion>
  <Accordion title="429 rate_limited">
    Wait `Retry-After` seconds, then retry. See the backoff example in [Rate Limits](/rate-limits#handle-a-429).
  </Accordion>
  <Accordion title="400 bad_request">
    Read `error.param`. When it is `cursor` and `error.reason` is `cursor_expired`, request the first page again. Otherwise fix the named parameter.
  </Accordion>
  <Accordion title="500 internal_error">
    Retry once. If it persists, email [support@0xinsider.com](mailto:support@0xinsider.com) with `meta.request_id`.
  </Accordion>
</AccordionGroup>
